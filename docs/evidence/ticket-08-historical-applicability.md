## Release and evidence limits

- Upstream commits above are the immutable patch records; local source was inspected at the 2.45 retrofit baseline and relevant functions are named in the table. The `v2.45` annotated tag peels to `758a5a10e3a088eed05ebacf4e527b6c626a532f`, whose commit message names `branches/2-44-stable`; however, the annotated tag says “Tag 2.45 release,” `release/VERSION` reads `2.45`, and the Blender version header is 245. The source and tag identify the 2.45 baseline; the branch name is ancestry context, not evidence that the tag is a 2.44 release.
- The official archived 2.46 renderer notes confirm vector-blur work but do not enumerate this correctness commit. Commit date or ancestry alone is insufficient to claim exact inclusion in a release tarball. Where there is no official release-note statement or verifiable stable tag, the table explicitly says likely/uncertain.
- The official [2.49a/b fix summary](https://archive.blender.org/wiki/2015/index.php/Dev%3ARef/Release_Notes/2.49/2.49b/Bugs_Fixed/) is evidence for the named fix families, not proof that every trunk commit was included unchanged in a particular tarball. The official [2.49 release notes](https://archive.blender.org/www/development/release-logs/blender-249/index.html) are useful release context, not a substitute for checking source archives.
