# Bound native performance profile to supported evidence seams

Status: accepted

Ticket 09 uses measured Python operation timings, deterministic output oracles, and process peak RSS because macOS System Integrity Protection refuses Instruments Allocations attachment to the optimized legacy Blender executable. Release Time Profiler did not resolve Blender symbols, so it cannot support a function-level hotspot claim. The bundled Python 2.5 API cannot create a compositor graph and the repository has no historical graph fixture; enabling compositor on the preview scene would measure a no-op. The bundled `Image` API exposes load/save, pixel access, and pack/unpack but no image scaling/filter operation; no deterministic native-editor filter fixture was available to automate repeated timing. Therefore this harness records image conversion and sampling and explicitly marks image filtering/scaling as a no-go for this ticket. Record these limits as explicit no-go rows, preserve native GUI and background render evidence separately, and do not let missing instrumentation become a guessed allocation, compositor, or filter result. The native GUI's `Time:00:00.25` header was read after ten direct F12 renders, establishing a foreground completion baseline at the UI's 10 ms display resolution. Revisit compositor/filter profiling only when an authentic graph or repeatable filter operation/fixture is available; revisit allocation counts only with an attachable or in-process allocator seam that preserves the optimized build.
