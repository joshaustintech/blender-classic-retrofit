# 02: Read long text blocks without repeated traversal

**What to build:** Script authors can sequentially read long text blocks efficiently while edits, reset and EOF retain the original Python behavior.

**Blocked by:** [post-245-performance/01: Capture native workload profiles and output oracles](01-profile-and-oracles.md)

**Category:** enhancement
**Status:** wontfix

Approved by the maintainer on 2026-10-14. Blocked tickets remain non-executable until every linked prerequisite has a successful completion receipt. A no-go prerequisite does not unblock dependent integration.

- [x] Use the native profile to check `Text.asLines`; confirm it performs one forward linked-list walk per full-list call, with no repeated line-index traversal.
- [x] Reject the cached cursor backport: Blender 2.45 exposes no sequential read, iterator, seek, or reset API; safe invalidation for native editor, undo/redo, reload, and wrapper mutations has no bounded generation seam. Do not add new cursor API/state.
- [x] Run public API checks for empty text, empty and trailing lines, write, clear, snapshot stability, and unlinked-object error. There is no cursor/EOF/reset behavior in the existing API; inserting/deleting individual lines and reload are not exposed by this wrapper.
- [x] Keep legacy signatures and results unchanged by making no application-code change.
- [x] Measure complete `asLines()` calls on small and 50,000-line text. Keep the implementation unchanged; no cached-cursor comparison is applicable to this API.
- [x] Release embedded-Python smoke and existing `testtext.py` pass. Record actual local measurements only; do not transfer upstream timing claims.
